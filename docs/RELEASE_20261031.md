# Responsive main release — 2026-10-31

The operator accepted the physical tracking feel of `cdadbb8` and requested
promotion to main after checking the latest collection pipeline. They subsequently
requested higher joint reflex thresholds. This release preserves the accepted
teleoperation tracking parameters and raises **J2/J3 to 30 Nm**, leaving the other
joint thresholds at `[20, _, _, 20, 18, 18, 18]` and Cartesian thresholds unchanged.
The bridge uses these joint values for both contact reporting and collision
threshold arrays. No fault recovery or robot motion was performed by the agent.

## Physical feedback and limits of the evidence

The operator's accepted run was `responsive/trial_20261031_195323` with the earlier
J2=22/J3=20 Nm thresholds. Its command-interval P50/P95/P99 was
9.998/13.423/15.010 ms; this is scheduling telemetry, not measured mechanical lag.
It ended with `joint_reflex`, with J3 estimated external torque peaking at
20.009613 Nm. Thus accepted tracking feel does not establish fault-free insertion.
The new 30 Nm thresholds have been checked for actual loading, but have not been
tested in another physical contact trial. Higher thresholds permit more contact
load and do not remove the underlying load after insertion.

## Latest pipeline compatibility fixes

Comparison source: `/home/heinrich/pi05_plug_demo`, read-only. The latest source
added startup-confirmed auto-home, separately bounded home velocity/acceleration/
jerk, and a separate `teleop_max_velocity`. These features and their tests are now
supported in the control repository. General `bridge.robolab`/`collection.robolab`
templates match the latest source; the released responsive profiles retain their
tested 0.2 rad/s home reference setting. Teleop-only keeps explicit home confirmation;
recording launchers pass `--home-on-start` after their startup confirmation.

A material data-contract conflict was found and fixed before promotion:

- Accepted teleoperation uses J5–J7 reference speed 0.5 rad/s.
- At 15 Hz this can produce 0.0333 rad per step, beyond the existing 0.03 rad
  action range. The exporter correctly rejects such motion rather than clipping.
- `responsive_recording` caps J5–J7 reference speed at 0.4 rad/s, leaving room
  below that contract boundary; J1–J4 remain 0.3 rad/s. The other responsive
  tracking and collision parameters are shared.
- `collect_session.sh` selects this profile and preserves it when generating the
  per-session config. A `responsive` request without `--teleop-only` routes to it.
- Session startup rejects calibrated recording reference speeds incompatible with
  FPS/action scale before claiming control. Export still audits actual motion:
  reference speed alone cannot guarantee measured bounds under disturbances.

No action scale, normalization, camera geometry, data schema or training code was
changed. Eleven core data/transport/camera/contract files match the latest pipeline
byte for byte. Mixing old/new collection configs in one export remains prohibited;
export separate dataset versions as before.
